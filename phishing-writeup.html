01 Project Overview

The Phishing Email Analyzer is a Python-based cybersecurity tool that automatically reads and investigates email files (.eml format) to determine whether they are phishing or scam emails. It extracts key information from the email, runs multiple detection checks, assigns a weighted risk score from 0 to 100, and generates a professional PDF investigation report.

The project runs entirely in Google Colab, requiring no local installation. It demonstrates core email forensics techniques used in real-world cybersecurity investigations.

02 Problem Statement

Phishing is one of the most common and damaging forms of cyber attack. Attackers craft emails that impersonate trusted organizations — banks, payment platforms, government agencies — to trick recipients into revealing credentials or making fraudulent payments.

Why automate it? Manually identifying phishing indicators requires expertise and time. This tool automates the process by programmatically analyzing the technical structure of an email and flagging suspicious patterns that a non-technical user might miss.

03 How It Works

The analyzer runs a pipeline of six detection checks on each email file:

01
Email Parsing
Python's built-in email library parses the .eml file and extracts key fields: From, To, Subject, Reply-To, Date, and Received headers. The raw header data contains the ground truth about where an email actually came from — often very different from what it appears to say.
02
Display Name Detection
The sender's display name is checked against psychological alarm words: hacked, suspended, urgent, warning, blocked, virus. Legitimate companies never use panic language in display names — this is a high-confidence signal worth +30 points.
03
IP Address Extraction
Regex extracts IPs from Received headers with two validation layers — rejecting octets with leading zeros (e.g. 04.04.01.02) and excluding patterns matching the Date header to eliminate false positives. Private IPs appearing in public routing are flagged as anomalies.
04
Reply-To Mismatch Detection
A common phishing technique sets a legitimate-looking From address while pointing Reply-To at an attacker-controlled address. Example: From: support@paypal.com / Reply-To: attacker@gmail.com. Domain mismatch = +25 points.
05
Keyword Detection
The subject and body are scanned across four psychological categories: Urgency (immediately, expires), Fear (hacked, compromised), Credential Harvesting (verify, login, password), and Financial (payment, invoice, refund). Each category scores independently.
06
Weighted Risk Scoring
All findings combine into a single 0–100 score. Structural indicators (display name, Reply-To, IPs) are weighted higher than keyword matches, as they are harder to accidentally trigger in legitimate emails.

08 Challenges Solved

C1
False Positive IP Detection
Email Date headers (e.g. Sat, 4 Apr 2026 01:02:27) contain sequences that match IP address patterns. Initial regex extracted 04.04.01.02 as a valid IP. Solved by adding two validation layers: rejecting octets with leading zeros, and cross-referencing against the Date header.
C2
Scoring Calibration
Simple keyword matching produces too many false positives — a legitimate urgent business email would score high. Solved by weighting structural email indicators (display name, Reply-To, private IPs) more heavily than keyword matches, as these are far harder to accidentally trigger.
C3
PDF Generation in Colab
Google Colab lacks native PDF rendering libraries. Solved by generating a styled HTML report and using the browser's built-in print-to-PDF function, which produces higher quality output than any Python PDF library.
